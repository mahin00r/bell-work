# Privacy

Updated: 2026-10-21. Applies to Bell Work 2.0.0-beta.1.

Bell Work stores application records, subscription details, notes, links, preferences, reminder delivery history, and recovery copies in local browser-extension storage. It does not operate an account service, backend, analytics, telemetry, advertising, or cloud synchronization service.

Page capture runs only when you request it. It may read the selected page's title, URL, structured job metadata, site name, and selected text to prepare a draft. You review that draft before saving. The extension does not install persistent page scripts or request access to every website.

The packaged core makes no runtime network requests. Fonts and icons are bundled. Links to application sites, meeting pages, documents, or subscription providers open only when you choose them; those destinations have their own data practices. Development hot reload uses a local server.

JSON backups and calendar exports are files you choose to download. Bell Work does not upload them. Treat exported files according to the sensitivity of the records they contain. Bell Work does not itself encrypt local records or exported files.

Individual deleted items remain in recoverable Trash. Up to three local recovery copies can retain previous records after migration, import, or recovery restore. These copies remain on the same device and are removed along with records when you explicitly choose Delete all data. Removing the extension or its browser profile also removes its local storage.

Bell Work does not automatically submit applications, send messages, process payments, cancel services, or synchronize calendars. Manual payment records and planned cancellations reflect what you enter.

For project questions or issues, use the repository's issue tracker: [mahin00r/bell-work](https://github.com/mahin00r/bell-work/issues). Do not include private records or backup files in public issues.
